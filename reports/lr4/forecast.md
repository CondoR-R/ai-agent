# ЛР4: прогноз до основной серии

## Настройка
- Модель: Qwen2.5-1.5B-Instruct через llama.cpp, `--jinja`, температура 0, контекст 32768.
- Стенд: AgentDojo `v1.2.2`, suite `workspace`, 24 инструмента, 40 user tasks.
- Разбиение: dev = `user_task_n`, где `n % 4 == 0` (10 задач), holdout = остальные 30.
- Режимы: ReAct (выбор действия после каждого наблюдения) и plan-then-execute (план фиксируется до чтения результатов, модель подбирает только аргументы шага).
- Лимиты: 15 вызовов модели, 15 вызовов инструментов, 1024 выходных токена, порог входа 30000 токенов оценки.

## Прогноз

1. **Общая успешность будет низкой.** Маленькая модель 1.5B плохо следует tool calling на длинных схемах из 24 инструментов; ожидаю около 10–30% на holdout для ReAct и 7–25% для plan-then-execute.
2. **ReAct будет не хуже plan-then-execute на задачах, где следующий шаг зависит от прочитанного.** Типичный пример: найти файл/контакт/письмо, прочитать результат, затем выбрать адресата или состав действия. Plan-then-execute заранее не знает содержимое и может выбрать неверный инструмент/аргументы.
3. **Plan-then-execute может быть сравним на простых одношаговых задачах** (например, показать непрочитанные письма или найти событие), где план тривиален и не требует адаптации.
4. **ReAct будет дороже по входным токенам.** После каждого tool result история растёт и передаётся заново; при 3–6 шагах ожидаю медиану входных токенов у ReAct в 1.3–2.0 раза выше, чем у plan-then-execute. По числу вызовов инструментов различие должно быть небольшим, потому что оба режима ограничены 15 вызовами.
5. **Основные причины неудач:** неверные/неполные аргументы инструментов, отказ модели использовать инструменты, выбор неподходящего инструмента, превышение лимитов на длинных задачах, неверный финальный ответ при правильно выполненных действиях.

Этот прогноз фиксируется до запуска holdout и может не подтвердиться.
